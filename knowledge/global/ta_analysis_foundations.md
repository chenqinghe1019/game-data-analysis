# 数数 TA 分析主体与埋点

status: current
last_verified: 2026-11-11

## 先确定分析主体

分析主体决定行为如何去重和关联。数数 v6.0 的预置主体是 AE 用户 ID（`#user_id`）。项目可用事件属性或用户属性配置自定义主体，例如设备、账号、角色或平台 ID。主体列表和显示名取决于项目配置。留存、漏斗、分布和间隔可以在模型中切换主体。事件分析的「触发用户数」应核对当前指标提供的主体选项。分群与标签也按所选主体计算。 [项目分析主体](https://docs-v2.thinkingdata.cn/?version=v6.0&lan=zh-CN&code=project_entities&anchorId=)

| 分析问题 | 主体选择 |
| --- | --- |
| 玩家回访、账号活跃 | 选能代表目标玩家或账号的稳定键，跨角色、跨渠道时先确认合并规则。 |
| 创角后推进、按角色留存 | 使用项目定义的角色键，核对它在初始和回访事件中是否都可取。 |
| 安装、设备触达 | 使用设备粒度，核对设备字段在对应事件及渠道的覆盖。 |

一个账号有两个角色时，按角色查询会分别关联两条行为链。按账号查询，任一角色回访都可能让同一账号计入留存。渠道或区服分组可用来拆分结果，主体仍按模型选定的键计算。复现报表时先读现有配置，核对主体名称、来源字段、字段类型和空值。 [分析基本概念](https://docs-v2.thinkingdata.cn/?version=v6.0&lan=zh-CN&code=basic_concepts&anchorId=)

## 从埋点确认事件和属性

- **事件**记录发生的行为。用埋点方案核对事件标识、触发时机、上报端和重复触发的可能性。显示名相近的激活、创角、登录和登出可能代表不同环节。
- **事件属性**描述触发时的状态或行为上下文，适合筛选行为发生时的渠道、版本、动作枚举等。**用户属性**描述用户档案。做历史分析时，要核对读取的是当时的事件属性、历史快照还是当前用户属性。
- **虚拟属性**需核对来源、计算方式与适用事件。匹配 TA 界面的名称和字段标识后，确认筛选使用的数值或文本类型。
- **方案、元数据和实际数据**分别确认计划定义、当前可见字段和目标时间内的上报。事件缺失、属性空值异常或分组结构异常时，可按日期、事件、版本或来源缩小范围，核对入库、属性类型和空值率。 [埋点方案](https://docs-v2.thinkingdata.cn/?version=v6.0&lan=zh-CN&code=plan&anchorId=) · [数据验收](https://docs-v2.thinkingdata.cn/?version=v6.0&lan=zh-CN&code=validation&anchorId=)

## 根据问题选择模型

| 要回答的问题 | 模型和关键配置 |
| --- | --- |
| 行为发生多少次、多少主体触发、数值随时间怎么变 | 事件分析。核对事件次数、主体去重或属性聚合，再选时间和分组。 |
| 一批主体后来是否回来 | 留存分析。确定初始事件、回访事件、主体、入组日期、观察期限和成熟批次。 |
| 按顺序完成几步、在哪一步流失 | 漏斗分析。确定步骤事件、主体、事件顺序和转化窗口。 |
| 每个主体做了多少次、耗时多久、行为怎样串联 | 依问题分别用分布、间隔或路径分析，先核对主体和事件。 |
| 当前用户属性的分布，或涉及复杂跨表关联的口径 | 分别用属性分析或 SQL 查询。写 SQL 前核对表的粒度、关联键和项目定义。 |

模型结果可保存为报表，再汇集到看板。复现看板指标还要核对报表自身的筛选、看板筛选以及项目时区。 [分析运营平台](https://docs-v2.thinkingdata.cn/?version=v6.0&lan=zh-CN&code=user_guide_menu&anchorId=)

## 《下方了》新增留存示例

- 用「登录登出」事件 `in_out_log` 配置初始与回访。在初始事件行筛选「创角天数（+1）」（`#vp@create_role_days`）等于数值 `1`。回访侧沿用回访事件定义，创角天数条件只作用于入组。
- 项目埋点说明 `in_out_log` 覆盖登录和登出，动作字段为 `change_reason`。已在「数据表 → change_reason → 数据预览」核对：1 为登录，2 为登出。仅做登录留存时，在初始和回访事件分别设置「变化原因 = 1」。按事件存在计算时，将口径写为「登录登出事件」。
- 上述界面试算使用「用户」主体。跨渠道唯一玩家按项目规则使用 `nb_open_id`，复现角色或平台用户报表时确认对应的主体和去重键。
- TA「当日」是入组当天，「第 1 日」是次日。仓库业务约定 D1 为入组当天，所以业务 D7 对应 TA「第 6 日」，TA「第 7 日」对应业务 D8。汇报时写清列名及实际日期偏移，阶段留存率使用目标日已满期批次。

项目依据见仓库 `xiafangle_tracking.yaml`、`knowledge/projects/xiafangle/FACTS.md` 和 `knowledge/global/lifecycle_maturity.md`。
