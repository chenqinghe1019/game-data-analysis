# 统一指标字典

status: current
effective_date: 2026-10-08
last_verified: 2026-10-08

## 生命周期
- D1 = cohort 起始日当天。
- D2 = 起始日 + 1 天。
- Dn = 起始日 + (n-1) 天。
- “第 N 天”只统计目标自然日当天。
- “累计 N 天”统计起始日至第 N 天的累计值。
- 不得混用“当日值”和“累计值”。

## 新增
新增必须先明确 cohort 锚点。默认优先使用项目已确认的创角/注册日期。筛选新增日期只圈选 cohort，不限制后续事件扫描。

## DAU
当天满足项目指定活跃事件的去重玩家数。具体活跃事件按项目 FACTS。

## 留存
- 留存人数：cohort 玩家在目标日再次满足活跃条件的人数。
- 留存率：目标日留存人数 / 对应已成熟 cohort 人数。
- 分日留存默认每个 Dn 独立成熟。

## 付费
- 付费人数：指定范围内存在有效正向付费的去重玩家数。
- 付费率：付费人数 / 对应业务分母。
- 分母可能是新增、DAU、活动参与人数等，SQL 中必须明确。
- ARPU = 有效流水 / 总玩家数。
- ARPPU = 有效流水 / 付费人数。
- LTV = cohort 生命周期累计有效流水 / cohort 人数。

## 付费留存
默认定义为：基准日付费 cohort 在后续目标日再次登录/活跃的人数 / 基准日付费人数。
不要求后续再次付费。
后续再次付费应命名为“复购”“再次付费率”或“付费复购率”，不得混叫付费留存。

## 首日付费
只统计注册/创角当天实际有效 pay_log。不能用当前历史累充、查询区间累计付费代替。

## 付费分层
- 首日付费分层：先按玩家汇总首日有效付费金额，再分档。
- 累计付费分层：按生命周期/截止目标日/历史累充金额分档。
- 两种分层不可混用。
- VIP 分层与 R 档分层是不同维度。

## 参与率
参与人数 / 对应活动活跃人数或业务分母。
若存在占领/抢夺等子行为，应分别定义子行为参与人数。

## 人均次数
行为总次数 / 实际执行该行为的参与人数。
除非专题明确要求，不以活动活跃人数作人均次数分母。

## 资源
- 获取：正向流入。
- 消耗：负向流出或事件定义的消耗。
- 累计人均获取 = 累计获取总量 / 对应玩家人数。
- 累计人均消耗 = 累计消耗总量 / 对应玩家人数。
- 累计人均剩余只有在完整历史净流入可重建或有余额快照时才可定义为真实剩余。
