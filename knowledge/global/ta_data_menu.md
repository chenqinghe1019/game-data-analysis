# 数数 TA「数据」菜单与业务口径查证

status: current
last_verified: 2026-11-11

## 按问题选入口

| 菜单 | 页面 | 查什么 |
| --- | --- | --- |
| 数据管理 | 事件、事件属性、用户属性 | 找事件标识、显示名和类型。事件详情可查看关联事件属性、影响范围、变更日志，事件列表可查看昨日事件量和数据状态。 |
| 数据管理 | 数据表、指标、汇率换算 | 在数据表查字段、主键、关联属性、数据预览和历史版本。到指标页找项目已沉淀的口径。名称相近的指标需核对定义，例如「付费率_含代币消耗」。 |
| 埋点管理 | 埋点方案、数据验收 | 埋点方案分为埋点事件、公共事件属性、用户属性。数据验收用于核对已上报数据与方案的差异，例如字段空值率。「下方了」检查时界面显示暂无方案和验收记录，业务定义可继续查项目仓库的埋点文档。 |
| 埋点管理 | 上报管理、实时数据、Debug 模式 | 上报管理有上报统计和上报拦截。统计按入库时间展示已入库、异常入库、无法入库。实时数据有「实时入库」与「错误数据」，实时入库搜索最近 1000 条。Debug 模式用于接入测试设备后查单次上报与错误原因。 |
| 数据接入 | 接入指南、三方集成 | 接入指南列出项目接入参数与客户端、服务端 SDK 路径。三方集成用于查看已建方案，「下方了」检查时暂无方案。 |

## 业务口径怎么查

1. 从项目埋点文档定位业务动作、事件触发时机和上报端，再用「事件」详情核对事件和属性是否在当前项目可见。
2. 枚举字段带维度表时，进入「数据表 → 对应表 → 数据预览」核对代码与业务标签。看属性类型和关联表的主键，按界面的实际类型选值。同名属性在不同事件里需要结合各自触发场景解读。
3. 口径核对还需确认目标时间、事件量、分析主体、字段覆盖和已有项目指标。排查入库时区分事件发生时间与上报或入库时间。最近 1000 条实时样本找不到某事件，只说明该批抽样未命中。
4. 整理知识库时记录字段定义、映射和验证路径。避免抄录实时样本里的账号标识、设备标识及项目接入参数。

## 已核对的「下方了」示例

「数据管理 → 事件 → in_out_log」显示事件为「登录登出」，关联「变化原因」及「在线时长（s）」。该事件的变化原因关联 `change_reason` 维度表。维表预览确认 ID `1` 对应「登录」，ID `2` 对应「登出」。用于登录专属留存时，在初始和回访事件各加「变化原因 = 1」，初始事件另加「创角天数（+1）= 1」。以登录登出事件存在为活跃的旧口径，仍按相应报表定义复现。

此轮实测覆盖事件元数据和维表映射。加入动作条件后的留存数值需重新计算。
