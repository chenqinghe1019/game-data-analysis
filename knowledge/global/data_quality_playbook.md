# 数据异常排查 Playbook

status: current
effective_date: 2026-10-08
last_verified: 2026-10-08

## 指标全 0
优先检查：日期分区、事件名、项目后缀、JOIN 键、字段类型、成熟条件、渠道筛选。

## NULL 激增
检查：LEFT/INNER JOIN 是否改变、COALESCE 类型、标签快照日期、维表是否缺配置、空字符串是否未处理。

## 人数暴涨
检查：明细 many-to-many JOIN、账号/角色粒度混用、battle_uid 未与账号联合去重、商品维表一对多。

## 留存 > 100%
检查：分子是否重复计数；分子分母是否使用同一 cohort；付费留存是否误把多日事件次数当人数；是否跨角色重复。

## 流水翻倍
检查：payment 与 token_payment 是否重复相加；订单重复；JOIN 后订单行膨胀；分/元换算重复执行。

## LTV/ARPU 异常
检查：分母 cohort、成熟样本、金额单位、转端折算、是否把未成熟累计当成熟值。

## 某天/某区服突然 0
检查：分区数据是否存在、区服范围映射、合服后的 region_id/zone_id、行为事件是否换名、渠道/赛季筛选。

## 英雄上阵率异常
总战斗应按 #account_id + battle_uid 联合去重；英雄上阵战斗同样联合去重，不能用英雄记录行数代替战斗数。

## 战力异常
先确认是“当天最高”“截止当天最高”还是“最终值”；分位数样本应排除明显新手停留/异常无效样本后再比较。

## 订单重复
先按 order_id count(*)>1 查重复明细，再判断是真重复上报、状态多次变化还是正常多事件记录。
