# 弯月勇者：累计付费分层 × 活跃天数行为指标口径（2026-09-09）

## 项目表
- 用户表：`ta.v_user_44`
- 事件表：`ta.v_event_44`
- 商品配置：`ta_ext.product_id_44`
- 正式服 cohort：`ta.v_user_44.domain='release'`
- 付费金额：`pay_log.payment / 100`（元）

## 商品名称读取
- 所有付费商品名称统一通过 `pay_log.product_id = ta_ext.product_id_44.product_id` 关联商品配置表后，读取 `ta_ext.product_id_44.name`。
- 不直接使用 `pay_log.product_name` 做星际战令、七日目标、竞技场战令等商品名判断。
- SQL 中建议将两侧 `product_id` 统一规范为 `cast(try_cast(product_id AS bigint) AS varchar)` 后关联，避免 double/varchar 表达差异。

## 分组
- 累计付费分层沿用：`a_free`、`b_(0,6]`、`c_(6,30]`、`d_(30,100]`、`e_(100,300]`、`f_(300,500]`、`g_(500,1000]`、`h_(1000,+)`。
- 活跃天数：`in_out_log` 的去重活跃日期数。
- 生命周期型统计继续遵守成熟日期口径；本需求按至少成熟 7 天处理。

## 指标映射
- 星际巡航参与：`battle_result` 且 `battle_type=37`。
- 星际巡航参与次数：优先按 `battle_uid` 去重，缺失时以事件时间兜底。
- 星际巡航战令：实际名称为“星际战令”，配置表商品名 `ta_ext.product_id_44.name` 正则匹配 `星际.*战令`；不要写成“星级战令”。
- 七日目标礼包：第N天不是按玩家创角后的实际付费日期判断，而是直接按配置表商品名中的第N天标识匹配。商品命名格式示例：`七日目标-第6天`。因此第3/4/5天分别正则匹配 `七日目标-第3天`、`七日目标-第4天`、`七日目标-第5天`；不要再使用 `date_diff('day', 新增日期, 付费日期)+1=N` 判断礼包所属天数。
- 竞技场参与：`pvp_log`；参与次数优先按 `battle_uid` 去重。
- 竞技场战令：配置表商品名正则匹配 `竞技场.*战令`。
- 种植园参与：`item_log` 且 `item_num < 0` 即视为参与。
- 坐骑洗练：`mount_improve`，事件条数为洗练次数。
- 藏品抽取：`gacha_log` 且 `pool_type='collection'`，`award_ting` 的数组长度为本次抽取数（Trino 用 `cardinality(award_ting)`）。

## 比率/人均默认口径
- 玩法参与率 = 玩法参与人数 / 该累计付费分层×活跃天数组玩家数。
- 星际巡航战令付费率 = 星际战令付费人数 / 星际巡航参与人数。
- 竞技场战令付费率 = 竞技场战令付费人数 / 竞技场参与人数。
- 七日目标第3/4/5天礼包付费率 = 对应配置表商品名（`七日目标-第N天`）付费人数 / 该分组玩家数。
- 人均参与次数/洗练次数/抽取数默认以对应玩法参与玩家为分母。
