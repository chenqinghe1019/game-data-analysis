# 企微运营看板：社区账号与分游戏统计口径

status: current
effective_date: 2026-10-12
last_verified: 2026-10-12
scope: 项目35企微运营看板及后续相关维护
supersedes: 本专题此前以 wx_union_id / UnionID 作为人数去重与队列关联主体的口径；不覆盖游戏本体其他分析的身份规则。

## 人数主体

- 企微运营人数按项目35的 `"#account_id"`（社区账号ID）去重，不再按 `wx_union_id` 去重。
- 人数分子、分母、漏斗、参与队列、绑定后参与及回访 cohort 必须使用一致的社区账号主体，相关社区事件 JOIN 同步使用该字段。
- 非空账号口径保留：`nullif("#account_id",'')`。
- 角色数仍按 `game_role_id` 去重；队伍数仍按 `team_id` 去重；事件次数仍统计事件。人数主体更换不等于更改这些计数对象。
- 游戏行为关联使用社区 `game_role_id = 游戏项目 "#account_id"`。游戏项目的账号字段在此关联中代表游戏角色标识，不能直接用社区账号ID替代。

- 游戏登录、活跃和回流使用各自游戏项目，不能把项目35的社区登录/在线事件当作游戏本体行为。
- 账号主体变更已实施到下方了及一步两步当前保留的报表。2026-10-12用户随后授权一步两步按同一账号口径调整，替代此前暂不修改一步两步的范围限制。

## 已确认的指标边界

- 添加企微好友没有记录，用户要求直接忽略相关指标；后续不得用二维码识别、账号绑定或角色绑定冒充好友添加。
- 奖励发放通知不等于到账成功或实际领取成功。
- 分享点击表示分享操作，不直接代表邀请成功。
- 不支持的需求列明缺失事件、字段、状态或数据源；不得虚构埋点或数据。
- 关键业务疑问需要用户确认，枚举和关联键不能靠猜测。

## 比例与日期

- 本专题比例保持0–1，不乘100，不使用会自动乘100的百分比展示；固定保留4位小数。
- 已验证显示实现：`format('%.4f', round(1e0 * 分子 / nullif(分母, 0), 4))`。此实现返回显示字符串，需要数值下游运算时单独保留数值表达式。
- 使用浮点系数 `1e0`；本次核验发现 `1.0` 在相关引擎 decimal 除法下可能造成精度不足。
- 下方了与一步两步各保留报表及看板统一日期筛选默认均为2026-09-23至今日，包含今日未完结数据；更新时保留现有日期设置。
- 时间范围只限定对应 cohort/起点；后续转化或游戏行为扫描需覆盖原观察窗口。更换人数主体不得顺便更改窗口或成熟规则。

## 看板维护约束

- 修改前刷新，以当前看板实际保留报表为准；用户删除的报表不得自动恢复。
- 用户限定“只改人数主体”时，只改人数去重、相关身份关联及必要的口径说明；保留原布局、尺寸、图表类型、筛选、列顺序和比例格式。
- 下方了和一步两步均已按原指标顺序设置中图两列。一步两步在后续用户指令下同步中图布局和2026-09-23至今日日期筛选，替代此前保留原布局与日期的范围限制。汇总卡按所选日期显示期间绑定与参与率，回流/转化仍保留完整观察窗口。不得把局部布局要求推广到其他看板。
- 更新SQL后重新计算并确认成功，再保存；刷新核验保存结果。
- 同页切换SQL报表时，本次观察到标题已切换但编辑器仍保留上一报表内容。保存前核对完整SQL与报表名称；遇到此情况独立打开目标已保存报表，避免覆盖成上一张SQL。
- 更新报表可能改变图表默认展示，保存后核对并恢复原展示配置。
