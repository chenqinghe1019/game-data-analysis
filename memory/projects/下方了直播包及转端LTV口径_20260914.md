# 下方了直播包及转端 LTV 口径

更新时间：2026-09-14

## 统计主体与新增锚点

- 统一以 `nb_open_id` 作为唯一玩家主体。
- 新增锚点统一取同一 `nb_open_id` 在 `ta.v_user_41` 全量角色中的最早 `create_role_time` 自然日，即“nb_open_id 首次创角日期”。

## 转端 / 端包分类

分类仍然落在 `nb_open_id` 维度，但通过同一 `nb_open_id` 下不同渠道角色的最早创角时间判断，不使用 `in_out_log` 首次行为时间。

渠道范围：

- 微信小游戏（微小）：`channel_id = 3056211`。
- 端包渠道池：`3056210 / 3056215 / 3056219`。
- `3056218` 主播直播体验包明确排除。

同一 `nb_open_id` 下分别计算：

- `首次微小时间`：`channel_id = 3056211` 的角色中最早 `create_role_time`。
- `首次端包时间`：`channel_id in (3056210,3056215,3056219)` 的角色中最早 `create_role_time`。
- `统计渠道`：与 `首次端包时间` 对应的端包 `channel_id`，即 `min_by(channel_id, create_role_time)` 限定在端包渠道池内。

用户分类：

1. `转端用户`：存在首次微小时间，且 `首次微小时间 < 首次端包时间`。
2. `端包用户`：存在首次端包时间，且首次微小时间为空，或 `首次端包时间 <= 首次微小时间`。

只有至少存在一个端包渠道角色的 `nb_open_id` 才进入该报表。统计渠道名称通过 `ta_ext.channel_id_41.channel_id -> channel_name` 关联。

## LTV

- LTV 起点仍使用同一 `nb_open_id` 的全局首次创角日期，不因转端日期或首次端包日期改变。
- 支付事件：`ta.v_event_41.pay_log`。
- 有效支付：`payment > 0`，不限制 `pay_result`、`change_reason`。
- 金额单位：`payment / 100` 转元。
- LTV 支付必须绑定该 `nb_open_id` 的“统计渠道”：仅统计 `pay_log.channel_id = 统计渠道` 的支付，不汇总该 `nb_open_id` 其他渠道的支付。
- 因此同一 `nb_open_id` 若统计渠道为 `3056219`，其 LTV 只累计 `3056219` 的支付；微信小游戏、其他端包或其他渠道支付均不计入该行 LTV。
- LTV1 = 首次创角当天至当天、且统计渠道支付的累计金额 / 对应 cohort 新增人数。
- LTVn = 首次创角日起第 1～n 个自然日、且统计渠道支付的累计金额 / 对应 cohort 新增人数，统计到 LTV30。
- 输出维度至少包括：首次创角日期、用户类型（转端用户/端包用户）、统计渠道 ID、统计渠道名称、新增人数、LTV1-LTV30。
- 每个 LTVn 单独按成熟日期判断；观察截止统一为昨天。未成熟的 LTVn 返回 NULL。
