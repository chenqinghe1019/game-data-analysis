# 跨项目分群与标签表口径

更新时间：2026-09-09
适用范围：倍特工作室所有项目

## 1. 当前分群结果表

表名结构：`ta.user_result_cluster_xx`

其中 `xx` 为项目后缀，例如 41、44、42、22 等。

字段结构：

| 字段名 | 类型 | 说明 |
|---|---|---|
| `#user_id` | bigint | 用户唯一ID |
| `#varchar_id` | varchar | 字符串分析对象ID |
| `#double_id` | double | 数值分析对象ID |
| `tag_value` | varchar | 标签值（字符串） |
| `tag_value_num` | double | 标签值（数值） |
| `tag_value_tm` | timestamp(3) | 标签值（时间） |
| `tag_value_bool` | boolean | 标签值（布尔） |
| `tag_value_array_varchar` | array(varchar) | 标签值（字符串列表） |
| `cluster_name` | varchar | 分群标签名称 |

### 账号关联规则

如果业务表使用 `"#account_id"`，关联 `ta.user_result_cluster_xx` 时统一使用：

```sql
cast(a."#account_id" as varchar) = b."#varchar_id"
```

不要使用 `#user_id` 直接关联 `#account_id`。

## 2. 历史标签表

表名结构：`ta.history_tag_xx`

其中 `xx` 为项目后缀。

字段结构：

| 字段名 | 类型 | 说明 |
|---|---|---|
| `#long_id` | bigint | 用户唯一ID |
| `#varchar_id` | varchar | 字符串分析对象ID |
| `#double_id` | double | 数值分析对象ID |
| `tag_value` | varchar | 标签值（字符串） |
| `tag_value_num` | double | 标签值（数值） |
| `tag_value_tm` | timestamp(3) | 标签值（时间） |
| `tag_value_bool` | boolean | 标签值（布尔） |
| `tag_value_array_varchar` | array(varchar) | 标签值（字符串列表） |
| `cluster_name` | varchar | 分群标签名称 |
| `$tag_date` | integer | 历史版本日期，格式固定为 YYYYMMDD，例如 `20240101` |

### 账号关联规则

如果业务表使用 `"#account_id"`，关联 `ta.history_tag_xx` 时统一使用：

```sql
cast(a."#account_id" as varchar) = b."#varchar_id"
```

不要使用 `#long_id` 直接关联 `#account_id`。

### `$tag_date` 日期规则

- `$tag_date` 是 `integer`，值形如 `20240101`，不是 `date`，也不是 `'2024-01-01'` 这种字符串。
- 生命周期分析按新增第 N 天匹配历史标签时，先算出目标自然日，再转成 `YYYYMMDD` 整数与 `$tag_date` 精确匹配。
- 统一写法示例：

```sql
h."$tag_date" = cast(date_format(target_date, '%Y%m%d') as integer)
```

- 若 D1 定义为创角当天，则新增第 N 天目标日期为：

```sql
date_add('day', N - 1, date(create_role_time))
```

### 历史 VIP 标签口径

- 历史 VIP（截止当日 VIP）使用标签：`vip_level_today`。
- 在 `ta.history_tag_xx` 中筛选：

```sql
cluster_name = 'vip_level_today'
```

- 历史 VIP 值使用 `tag_value`；`tag_value` 为 NULL 或空字符串时统一按 VIP 0 处理。
- 推荐写法：

```sql
coalesce(try_cast(nullif(trim(tag_value), '') as double), 0)
```

- 新增第 N 天分析必须用该玩家“新增第 N 天对应自然日”的 `$tag_date` 去匹配 `vip_level_today`，不能使用当前 VIP 替代历史 VIP，也不能拿同一个 VIP 值覆盖 D1～D14。
- 历史 VIP 标签关联建议使用 `LEFT JOIN`；某玩家某日缺少标签快照时，不应直接把该玩家从样本中删除，缺失标签按 VIP 0 处理。

## 3. 使用优先级

- 需要当前分群/当前标签结果：优先使用 `ta.user_result_cluster_xx`。
- 需要历史某一版本标签：使用 `ta.history_tag_xx`，并筛选 `$tag_date`。
- 后续所有项目 SQL 涉及这两类表时，默认遵循本口径。
