# 跨项目生命周期成熟统计口径

更新时间：2026-09-09
适用范围：倍特工作室所有项目
优先级：本文件为当前最新成熟统计统一口径；如旧文件存在“按最大观察天数统一成熟”的默认描述，以本文件为准。

## 默认规则

生命周期分日指标默认按“对应天数分别成熟”统计。

- D1 = 起始日当天，对应 `days=0`。
- D2 = 起始日+1，对应 `days=1`。
- Dn = 起始日+(n-1)。
- 对 `days=k`，成熟条件：

```sql
date_add('day', k, start_date) <= date_add('day', -1, current_date)
```

因此同一日期筛选区间内，各 Dn 可以使用不同的已成熟样本范围；不能因为表里同时展示 D1～D14，就先统一要求所有 cohort 已完整成熟到 D14。

例如今天为 2026-09-09，筛选 2026-09-02～2026-09-08 新增：
- D1：09-02～09-08 均成熟。
- D2：09-02～09-07 成熟。
- D3：09-02～09-06 成熟。
- ……
- D7：仅 09-02 成熟。
- D8～D14：当前无成熟样本，应为空/不计。

## 事件延展

日期筛选只圈选 cohort 起始日期；事件按玩家/区服/活动从起始日自动延展到当前 Dn 的目标日期，不用独立事件日期筛选器把后续日期截断。

## 例外

只有用户明确要求“D1～Dn 使用完全一致 cohort / 同一批成熟样本”时，才按最大观察天数统一筛成熟样本。

该规则适用于生命周期、LTV、留存、付费、活跃、关卡、阵容、英雄养成等分日分析。
