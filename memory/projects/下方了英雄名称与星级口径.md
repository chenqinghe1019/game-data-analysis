# 下方了英雄名称与星级口径

更新时间：2026-09-09
适用项目：下方了 v41

## 英雄维表

表：`ta_ext.heroid_41`

核心字段：
- `heroid`：英雄ID
- `heroname`：英雄名称
- `star`：配置初始星级

## role_id 实际上报规则

当前 `role_obtain_log`、`role_upstar_log`、`role_back_star_log` 等英雄事件中的 `role_id` 实际上报的是英雄名称，而不是数值英雄ID。

因此需要关联英雄维表时，统一使用：

```sql
cast(e.role_id as varchar) = cast(h.heroname as varchar)
```

不要使用 `role_id = heroid`。

英雄展示名称优先使用 `ta_ext.heroid_41.heroname`；若维表未匹配，可回退事件中的 `role_id` 原始值，避免数据丢失。

## 初始星级与当前持有星级

英雄初始星级优先使用英雄获得事件 `role_obtain_log.init_star`。

若 `init_star` 为空，则回退使用 `ta_ext.heroid_41.star`：

```sql
coalesce(
    try_cast(e.init_star as double),
    try_cast(h.star as double)
)
```

后续星级变化：
- `role_upstar_log.nstar`：升星后的当前星级
- `role_back_star_log.nstar`：回退后的当前星级
- `role_lost_log`：该 `ins_id` 不再视为持有

按截止某日重建英雄当前星级时，应以 `ins_id` 为实例维度，按事件时间取最后一个非空星级状态；当前是否持有则按最后一个获得/升星/回退/扣除事件判断。

同一玩家如果当前持有多个同名英雄实例，玩家该英雄星级取当前持有实例中的最高星级。

## 生命周期成熟口径

D1=创角当天，D2=创角+1天，以此类推。

分日指标默认每个 Dn 独立判断成熟：只有 `创角日 + (N-1) <= 昨天` 的玩家才进入该 Dn 指标。

D14/D30汇总专题按对应周期完整成熟：
- 前14天汇总：只统计 `创角日+13 <= 昨天` 的玩家，英雄状态取 D14 截止状态。
- 前30天汇总：只统计 `创角日+29 <= 昨天` 的玩家，英雄状态取 D30 截止状态。

## 历史VIP口径

历史VIP使用 `ta.history_tag_41`，标签：

```sql
cluster_name = 'vip_level_today'
```

当前已确认关联键为：

```sql
ta.v_user_41."#user_id" = ta.history_tag_41."#long_id"
```

生命周期目标日通过 `$tag_date` 精确匹配，`$tag_date` 为 integer YYYYMMDD：

```sql
h."$tag_date" = cast(date_format(target_date,'%Y%m%d') as integer)
```

VIP值固定取 `tag_value_num`，NULL或缺失标签按VIP0处理。

D14汇总使用D14当天历史VIP；D30汇总使用D30当天历史VIP。

## D14/D30英雄持有率与星级分布

- 成熟玩家数：对应周期已经完整成熟、且属于该目标日历史VIP的玩家数。
- 英雄持有人数：目标日截止时当前仍持有该英雄的成熟玩家数。
- 英雄持有率 = 英雄持有人数 / 成熟玩家数。
- 星级分布：先对每个玩家取该英雄当前持有实例中的最高星级，再按星级统计人数。
- 星级分布率 = 该星级人数 / 英雄持有人数。
- 完全没人持有的英雄保留一行，星级展示为“无获取”，持有人数和持有率为0。
