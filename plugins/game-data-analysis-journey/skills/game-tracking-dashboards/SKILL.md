# 游戏埋点和看板

结合 [IAA 与企微指标卡](references/tracking.md) 工作。先阅读实际埋点文档的事件、用户属性、公共事件属性与接入说明，再在相应 TA 项目核对实时元数据与样本。

1. 从业务问题确定指标、去重键、分母、触发时机、环境、属性类型、单位、枚举与上报端。标注所需维度、窗口和缺报处置；区分预置属性、事件属性和用户属性。
2. 能复用现有报表和事件时先复用。对照板式、趋势、漏斗和筛选条件，替换为目标游戏实际存在的事件。变更现有卡片前锁定目标项目、看板及卡片；确认保存后回读实际公式和过滤条件。
3. 按访客、设备、账号和角色区分分析粒度，验证跨端身份拼接与去重。单账号多角色通常用角色作业务粒度，账号作为自定义属性；与目标游戏已生效 ID 规则核对。区分开发、测试、正式；确认时间来源和跨端排序，避免同义事件重复统计。
4. 核对可用性和样本。用一条已知路径核对事件顺序、ID、时间和分支失败码；检查字段名大小写、同名异型、上报重复缺漏、分母来源、聚合与重复绑定。对展示、点击、完成、奖励发起和到账分别标注。
5. 某个动作数据拿不到时，用可观察事件作代理并说明，例如用欢迎语链接点击衡量响应。分析和交付优先使用聚合数据；需要定位异常再使用授权明细。

倍特工作室任务先按 [仓库导航与更新流程](../game-data-analysis/references/knowledge-sync.md) 核对适用项目的 GitHub 最新业务口径，并沿用已确认长期知识的回写方式。
