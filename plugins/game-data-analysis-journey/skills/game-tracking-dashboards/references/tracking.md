# IAA、游戏社区与企微

## 《一耍就上头》

- 目标项目 `IAA_Game`，搭建时参考“方块也疯狂”现有看板。先复制适用分析结构；从目标游戏埋点复核匹配，检查游戏名、包体、渠道、正式环境和时间过滤。发布前用短窗口对比原事件。
- 广告渗透率 = 当日去重广告观看人数 ÷ 当日活跃。激励广告 `ad_log` 在播放结束时上报；`ad_button` 为弹出/点击；插屏 `ad_Interst` 为展示。明确完成观看还是展示的统计条件；跨类型总人数去重。可另列按广告位、类型拆分的曝光、点击、观看/完播、广告次数及每观看用户频次。
- 用户与玩法：`active_log` 在登录节点触发，需按约定节点和用户键去重。自动采集有 `ta_app_install`、`ta_app_start`、`ta_app_end`、`ta_app_crash`，避免用启动量替代用户数。战斗用 `battle_start`、`battle_result`，每日挑战用 `daily_start`、`daily_progress`、`daily_result`；金币变动 `res_change`，另有 `top_level`、`best_score`、鱼缸、鱼获取/售卖及背景方块解锁使用。
- ID 按该文档检查 `game_name` + 角色 ID 的拼接约定，无角色系统时核对 `nb_open_id`。与游戏社区的社区账号 ID 结构区分。

## 游戏社区与企微

| 面板 | 要点 |
|---|---|
| 核心目标 | 入口曝光和角色绑定成功人数看日值、累计、趋势。添加率 = 新增企微好友 ÷ 入口点击，绑定率 = 绑定成功 ÷ 新增企微好友，企微活动参与率 = 活动参与 ÷ 绑定成功。绑定后 7 日回流按成熟的绑定队列观察，规则明确后落表。 |
| 建联漏斗 | 入口曝光/点击 → 跳转微信 → 授权成功或二维码展示/识别 → 添加企微 → 欢迎语链接 → 打开绑定页/登录 → 角色绑定 → 奖励到账或参与活动。兼容各真实路径。逐环节展示人数、转化和失败原因，用交集或用户级顺序约束验证；保留漏斗分支。 |
| 角色绑定 | 按渠道、区服、绑定方式拆使用量和成功率，监控失败码、绑定时长及分布、重复绑定、换绑、解绑。身份关联区分游戏角色、社区 UID、企微联系人，与隐私授权一致。 |
| 企微好友 | 总量、新增、净增（新增减删除/流失）、来源、承接助手、欢迎语链接点击率、24 小时绑定、删除/失联、未绑定、3/7/14/30 日沉默分层。 |
| 企微活动 | 触达、点击、参与、完成、重复参与、完成时长、回流；按活动、活跃/回流状态和付费层级拆分。 |
| 奖励 | 见面礼、周期礼包领取率、抽奖人数/次数、到账状态与时长、补发状态、重复/异常领取。用实际到账状态验证闭环。 |
| 邀请 | 发起/被邀、添加、绑定、有效邀请率（添加且绑定人数 ÷ 被邀人数）、人均有效邀请、阶梯进度、回流、异常邀请关系。 |
| 回流与留存 | 绑定后活跃天数、登录频次、不同观察窗回流；区分请求的活跃和回访。 |
| 异常监控 | 跳转、授权、绑定与奖励失败；身份关联失败、上报延迟/缺失、重复绑定和异常参与。 |

- 社区埋点有 `click_log`、`click_log_index`、`log_in_out`、`uid_in_out`、发帖过审 `add_post_success`、帖子浏览 `user_access`、签到 `user_check_in` 等。正式环境示例 `env=prd`，使用 `sns_id` 区分社区。常规 `#account_id` 示例为 `jsccsns_prd_10001`，一步两步历史例外保持原两段式。
- “添加企微需求”工作表要求复用页面/点击/奖励、`h5_team_join`、`h5_team_create_success`。角色绑定成功用服务端 `game_role_bind`，考虑 `source=3`；`account_bind` 是社区账号绑定，须区分。用 `wechat_qr_show` 和 `wechat_qr_scan` 看二维码链路，后者是长按拉起的信号；实际新增好友要用企微新增好友记录。用 `h5_activity_claim_reward` 看领取请求，到账状态由成功回执或发放状态核对。五人组队成功事件会给五名队员分别上报，算队伍时按队伍 ID 去重。
- “消息已读”不可可靠取得时，使用链接点击、小程序打开或活动参与等可验证行为。对绑定后第 7 天、7 日内回流和仅统计已完成观察窗口分开定义。
