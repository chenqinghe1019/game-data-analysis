# SLG 口径与历史案例

## 批次和日期

- 历史项目为 TA 项目 41，沿用“SLG 活跃付费”原看板。已见批次、合服原报表 6248、6299。复用时先确认报表仍对应当前问题。
- 2026-11-17 快照曾用首批 1–146、第二批 147–1236。后续按实际进入 SLG 更新为第二批 147–1040（进入日 11/16），首批 1–146（进入日 11/11）。按当前请求选版本，避免混合不同范围或滚动快照。
- 九个历史合服小组：首批 1–45、46–121、122–133、134–146；第二批 147–299、300–432、433–559、560–825、826–1040。需要单独看某组时输出子组和剔除后剩余组。子组同时参与原总体和剔除版时防止二次合计。
- 前后 7 日、8–14 日是不同窗口。以北京时间最后一个完整入库日为上界，一般至昨天；两个周期用共同成熟天数，列明实际日期及天数。826–1040 案例中剔除 11/17 关服日，前侧同步去掉对应位置；另留未剔除的原口径。整个第二批剔除 826–1040 的情景用 147–825 重算。
- 若计算区服对大盘流水变化的贡献百分点，用同一个大盘前期流水作分母。用组净变动 ÷ 大盘净变动表示贡献比例时，其他组可能反向抵消，比例可以超过 100%；大盘变动近零时优先给金额。

## 回访和 VIP

- VIP 按进入 SLG 前历史最高实际等级固定分层。无历史记录在确认数据规则后归 V0。分档 V0–V3、V4–V6、V7–V9、V10+。不要用进入后 VIP 历史改变分层。
- 基准日标 D1，次日 D2，3 日累计 D2–D4，7 日累计 D2–D8。通过条件匹配角色且窗口内至少活跃一次来统计累计回访；同时列前后基准日、窗口日期、样本、回访人数及比率。异常窗口只用首个有效观测日时据实命名。
- 估算多/少回访人数 = 上线后基准样本 ×（上线后回访率 − 上线前回访率）。实际人数差同时受样本变化影响。小样本报告人数并提示波动程度；合计回访用回访人数与基准人数重算。
- 诊断 SQL 的项目 41 基准事件曾出现 `in_out_log` 的事件 `server_id` 全空；不得用空字段直接筛区服。需验证角色关联键、唯一性及 TA 看板使用 `zone_id` 或 `server_id` 的条件，再做分服关联。200/2000/9000 是项目 22 累计付费代理阈值，只有明确需要时才按代理层级使用并如实命名。

## 商品拆解

- 礼包占总流水 = 礼包流水 ÷ 同窗总流水。其他付费流水 = 总流水 − 礼包流水。观察期 LTV 贡献按原报表定义为周期流水 ÷ 对应新增人数（各原始服首日新增之和），注明它的窗口。礼包购买率保留看板分母，未核实时注明。
- 复拉时对商品 ID、原始名称、分类表与刷新时间留痕。拆大盘、礼包/非礼包、类别、单品；可同时列总流水占比、单品占礼包流水、净增量贡献。计算变化时如前期已有礼包流水，用两期礼包差额。合计、明细与礼包大盘差额单列。历史方案有城镇特惠、全面城镇、强化城镇等单品分析。
- 历史排除情景曾涉及：赛季英雄雅典娜、萱萱升星、天魔法印、限时双战令、S2赛季礼包、天师驱诡、S2赛季战令、萱萱补星包、闹诡金矿。使用当次确认的商品 ID 和同名别名；计算“剔除后的 SLG 占比”时用同一剩余流水分母。金额剔除只改变符合条件的流水；付费率若也要求更新，需按剩余订单重算去重付费人数。
- 有其他付费下滑时可提出消费预算转移的可能性。要估净新增或替代规模，需匹配版本、同期活动、区服阶段和玩家分层等可比条件。
