# 数数 TA 分析

## 进入项目

- 在用户可用的浏览器会话中打开 TA。飞鱼实例入口为 https://ta-data.feiyu.com。优先复用已登录的标签页。若停在账号登录页，请用户在浏览器完成登录。
- 用顶部项目选择器切换到用户指定的项目，等页面加载完成后核对项目名。「下方了」是已实测项目。后续任务以用户指定的项目或当前已明确的项目为准。
- 从顶部「分析」进入相应模型。临时探索从模型菜单打开新查询，避免直接编辑看板上的现有报表。若用户给的是现有报表链接，先核对报表、项目和当前配置。

分析主体、埋点口径或跨模型选择需要核对时，阅读 [数数 TA 分析主体与埋点](references/ta_analysis_foundations.md)。

要核对元数据、维表枚举、上报或数据接入时，阅读 [数数 TA「数据」菜单与业务口径查证](references/ta_data_menu.md)。

## 看板搭建与迁移

在搭建或跨项目迁移看板、配置公共指标、虚拟属性、用户标签或分群前，先读取倍特工作室工作区的 `knowledge/global/ta_dashboard_migration.md`，再通过 `knowledge/CANONICAL_INDEX.md` 找到源项目和目标项目口径。工作区不可用时，查阅 [GitHub 上的看板迁移指南](https://github.com/chenqinghe1019/game-data-analysis/blob/master/knowledge/global/ta_dashboard_migration.md)。服务器生态看板的数数配置与起算日期见项目口径，固定日期按对应看板要求核对。

## 事件分析

1. 在「分析指标」选事件，再选统计口径。「总次数」统计事件发生次数。「触发用户数」按界面所选分析主体去重，核对主体后再描述结果。分析事件属性时，核对字段类型、含义和聚合方式。
2. 在结果区设置日期范围和粒度，查看实际起止日期。「过去 7 天」在实测中截至昨日。复现其他看板时，核对日期、时区和筛选范围。新查询需要按分析目的配置这些条件。
3. 使用「全局筛选」限制纳入计算的数据，使用「分组项」拆分同一指标。点区块旁的「+」后，实测会先生成一个默认「账户ID」字段。点击字段名打开选择器，搜索目标字段。遇到同名字段，核对来源及字段标识。筛选需选择运算符和值，并确认值已出现在条件行。
4. 点「计算」，等查询完成。核对趋势图与明细表中的指标、日期、分组和阶段汇总。修改条件后重新计算，以新结果为准。分组显示如有「已展示 / 总分组」计数，核对是否存在隐藏分组再汇报。去重指标用同口径的阶段汇总，避免直接相加每天或各组的去重人数。
5. 按任务选择图表。实测事件分析结果区同时有趋势图和明细表，可在可视化配置中调整数值显示、总计、排序等。遇到「当前查询无数据」，先核对项目、事件、日期和筛选条件，必要时用同项目的无筛选查询验证基线。

### 已实测的复现路径

「下方了」→「分析」→「事件分析」→「激活」→「总次数」→「按天」→「过去 7 天」→「计算」。先确认整体趋势和阶段汇总，再加「分组项 → 事件属性 → 操作系统（#os）」并重算。然后加「全局筛选 → 事件属性 → 操作系统（#os）→ 等于 → Android」并重算。确认结果只剩 Android，且阶段汇总与筛选前的 Android 分组一致。此例的日期随查询日滚动。

## 留存分析

分析次留、七留或回访时，阅读 [留存分析](references/retention.md)。实测覆盖「下方了」的新增留存口径（初始登录且创角天数等于 1）、观察期限、留存表和隐藏不完整数据。

## 漏斗分析与分布分析

核对有序步骤转化，或按每个主体的次数、天数或属性聚合结果划分区间时，阅读 [漏斗分析与分布分析](references/ta_funnel_distribution.md)。已实测漏斗的窗口与转化、流失结果，以及分布的自定义区间、按天和合计。

## 其他分析模型

「分析」菜单还包括属性、间隔、路径、归因、SQL 查询、排行榜和热力地图。按当前界面核对参数和输出。

## 保存与交付

- 临时分析核对计算结果即可。用户要求保存时，核对报表名称、项目和目标看板。测试任务只保存到明确的测试位置。未指定且无法从界面辨认测试位置时，先完成查询预览，再询问保存位置。
- 保存后从目标看板重新打开，核对报表模型、日期、筛选、分组和计算结果。标签或分群规则有变更时，确认新计算完成后再验收依赖报表。
- 汇报使用的项目、指标口径、日期范围、筛选与分组，并给出计算结果和保存状态。指出影响解读的限制，例如查询无数据或只展示部分分组。
