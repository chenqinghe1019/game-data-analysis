# 留存分析

## 配置与计算

1. 在目标项目打开「分析 → 留存分析」，核对左上「对…进行分析」的分析主体。选择「初始事件」定义入组行为，选择「回访事件」定义后续行为。新查询可能给两个位置填入相同的默认事件，逐项检查。
2. 分别设置结果区的留存期限和日期范围。「7日」生成当日到第 7 日的列，「过去 7 天」选取初始事件发生的日期。第 N 日留存衡量每个入组批次在初始事件日期之后第 N 日完成回访事件的情况。查看完整七留时，按项目当前日期和数据到数情况，给每个批次留足七个已结束的观察日。
3. 通过事件行右侧的漏斗图标添加该事件独立的筛选。仅用于入组的条件放在初始事件行下。需要同时限制两侧事件或拆分结果时，分别按任务设置「全局筛选」和「分组项」。
4. 点「计算」并等留存表加载。调整日期并点「应用」在实测中会自动重算，先查看是否已有计算在运行。核对「留存」模式、初始事件人数、各日回访人数和留存比例。按日期读单批次，按「阶段值」读所选日期的汇总。

## 结果核对

- 带星号的格子表示观察期尚未结束。实测打开「可视化配置 → 通用设置 → 隐藏不完整数据」后，带星号的数值消失，已有的完整阶段值保留。比例显示为「-」时，先核对对应观察日是否有完整批次。
- 阶段留存率用该观察日完整批次的回访人数之和除以这些批次的初始人数之和。表头下的初始事件人数汇总可能包括尚未满期的批次。校验阶段比例时，用对应观察日的完整批次分母。 [数数科技阶段值说明](https://doc.thinkingdata.cn/ta-manual/latest/user_guide/analysis/retention/retention_overview.html)
- 汇报时说明项目、分析主体、初始和回访事件、入组日期、观察期限以及比例是否完整。「使用同时展示」「使用关联属性」与留存分组的具体行为尚未在该实例实测，按实际任务核验。

- 复现仓库业务 D 编号时，D1 为入组当天，业务 D7 对应 TA「第 6 日」。汇报 TA「第 7 日」时注明是入组日期后第 7 天。

## 「下方了」新增留存

1. 打开「分析 → 留存分析」。实测主体选「用户」，初始事件和回访事件都选「登录登出（in_out_log）」。搜索「登录」可找到该事件。「数据表 → change_reason → 数据预览」已确认 1 为登录、2 为登出。前一次试算按事件存在计算。若任务要复现指定报表，核对其分析主体和事件条件。
2. 点**初始事件**右侧的漏斗图标，选择事件属性「创角天数（+1）」（字段标识 `#vp@create_role_days`），运算符选「等于」，输入并选中数值 `1`。检查初始事件下显示「等于 1」。若界面生成了默认「账户ID」空条件，移除多余的条件行。
3. 仅做登录留存时，在初始事件与回访事件各自的筛选中添加「变化原因（change_reason）= 1」，创角天数条件只加在初始事件。按事件存在口径复现时，核对报表原有条件。添加登录动作筛选后的结果需要重新计算。
4. 要复现完整七日观察，期限选「7日」，模式选「留存」，日期可用动态范围「14 天前 → 8 天前」。点「计算」后，确认表头显示「登录登出用户数」，再用第 N 日回访人数和对应的初始人数核对阶段比例。日期随查询日滚动，复现时以实际到数为准。
