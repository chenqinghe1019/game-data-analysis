# 输入映射与数据质量

## 通用输入

记录数据日期、来源文件、字段含义和单位。不同报表的行粒度不一致时分别处理；不得按行号直接拼接。日期缺失不能以文件修改时间替代业务日期。

## 数数采集器 JSON

可识别结构：

```json
{
  "schemaVersion": "0.1",
  "dashboardName": "示例看板",
  "reportName": "示例报表",
  "filters": {"日期": "过去7天"},
  "collectedAt": "2026-01-08T09:00:00Z",
  "rowCount": 2,
  "headers": ["日期", "活跃人数"],
  "rows": [["2026-01-06", "100"], ["2026-01-07", "110"]]
}
```

以上为模拟数据。`headers` 对应 `rows` 的列位置，每行宽度必须一致；存在 `rowCount` 时检查与实际行数一致。`collectedAt` 为采集时间，不是数据日期。

“阶段值”“合计”等行属于源报表汇总，不作为单日数据参加环比。`-`、空字符串和 null 保留缺失含义，不默认转换为零。逗号千分位、百分号和货币符号需按明确规则解析；含百分号的 `12.3%` 存为 0.123，已为比例的数值不能再除以 100。

项目名与单位来自用户或元数据，不根据项目编号猜测。来源与筛选条件可放在工作簿说明区域；外部分享时不自动附带内部网页地址、角色明细或账号字段。

## 代表性校验

- 比较人数、金额、比率各一项（如果存在），确认 Excel 和 PNG 与输入一致。
- 上期零值、缺失值不生成无穷大或虚假的 0% 环比。
- 未成熟留存/LTV 显示缺失，不能将缺失解释为下滑。
- 只有用户要求的期间进入日报；历史预览不能改写成今日实时数据。
