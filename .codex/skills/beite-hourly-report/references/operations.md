# 运行、验证与故障处理

## 环境

Windows、PowerShell 7（`pwsh.exe`）、Google Chrome；Node 需支持 `node:sqlite`、`URL.parse` 等现有接口。原机器使用 Codex 自带 Node。浏览器依赖 Playwright；Excel 与 PNG 依赖 Codex 的 `@oai/artifact-tool`，通过 `GRAVITY_NODE_MODULES` 指向依赖目录。

现有启动器默认 Node：`%USERPROFILE%/.cache/codex-runtimes/codex-primary-runtime/dependencies/node/bin/node.exe`。迁移机器先核对目录及依赖，不声称 npm 全新安装即可复现。

`panel.ps1 -Managed` 使用 8732 端口；直接 `panel.mjs` 默认 8731，避免打开错后台。运行中的配置在 LocalAppData，修改仓库 defaults 不等于修改已保存配置。

## 定时

Windows 任务名 `GravityWeComReport`。安装器配置登录时启动、每分钟保活、异常重启；后台约每小时开头20分钟尝试按顺序派发，作业串行。

- 锁屏但用户仍登录、机器清醒且网络和 Chrome 会话正常时，计划任务可以继续运行；不保证睡眠、关机、注销或会话失效时照常执行。
- 不需要让后台网页标签页常开；后台进程和所需浏览器会话必须可用。
- 00点属于前一天24点，取前一天全天累计；标题、日期、存档主键保持一致。
- 英雄目前每小时配置，实际开关读本机配置；不要把过去「每日12–24点」或「21点切换」当永久默认。
- 任务占用、缺 Webhook、首报时间未到、旧 slot 状态、派发窗口已过，都可能使某时点没有启动。

## 校验与重试

查询必须等待本次操作发出的匹配响应及数据落到页面；引力按日期、APPID、媒体父节点绑定，不能只按表格位置匹配。媒体成本、ROI 直接取原报表，本地除法用于验证，不能用错误分母替换原指标。

数数从指定看板刷新卡片并导出，核对更新时间、日期、CSV 表头、行数、媒体集合、人数金额与派生率。页面卡住时在现有重试次数内重新加载完整报表；重试不等于持续上下滚动。

联合调度最多3次尝试，失败后间隔45秒/90秒，单次超时5分钟；仍受20分钟派发窗口约束。普通 gravity / iaa / hero 的 slot claim 与联合重试并不完全相同，不能概称所有任务均已具备相同失败恢复能力。

Webhook 每条图文都有独立确认。图片发送成功而文字失败，补文字；两图有一张成功，恢复时跳过已确认图片。请求已发出但结果不确定时暂停自动重发，避免重复刷群。机器人单条 image 是一张图片；英雄为两次图片请求，再一次文字请求，不是单条消息携带两图。

## 排查顺序

1. 只读检查任务状态、`/api/job`、各项目 `/api/config` 与脱敏日志，确认是没启动、取数失败、导出失败还是发送失败。
2. 检查当前小时 slot 和消息状态，不盲删标记；查原始备份是否已经取得，避免重拉后冒充历史整点值。
3. 登录过期时由脚本按已保存凭据填入、勾选同意条款、登录；遇验证码或账号安全验证需要按实际机制处理，不承诺绕过。
4. 页面加载或查询超时按配置刷新重试；校验失败停止推送并保存证据，不填0凑表。
5. Excel 被占用：SQLite 可能已成功保存，关闭正式累计文件后从档案重建；不要丢弃或重复累计同一小时。
6. 只在作业空闲时重启服务。不要同时启动第二个后台抢端口 / 浏览器 / 工作簿。

## 修改验收

改动先离线核对：跨天24点归属、历史24点保留、同小时更新不重复、人工底档保持、媒体加权、缺失显示、图文部分成功恢复。只对涉及逻辑运行有意义的断言。预览、重发和上线是不同动作；用户要求模拟时，不写正式库，不触发 Webhook。

对在线文档的读取或编辑如被工具 / 站点限制，不换 CDP、Cookie、浏览器或脚本绕过；使用独立且正式授权的接口。旧外部文档受跨企业限制；2026-11-21用户提供的新内部文档已验证可读写，11点起在群播报成功后独立补缺，详见[文档同步](wecom-doc-sync.md)。

特别注意：英雄新 runner 的 `--preview` 只禁止发送，**仍会向输出目录旁的数据库追加**。模拟必须同时指定独立输出目录（包含独立数据库），不能只加 `--preview` 并保留正式默认路径。联合旧 runner 的 preview 分支不调用正式追加接口，仍应给独立文件名并检查路径。
