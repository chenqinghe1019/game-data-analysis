# 存档、追加与恢复

SQLite 是分时记录来源；累计 Excel 是展示产物，不把截图或已折叠 Excel 当完整历史。

## 记录与主键

表 `snapshots(date TEXT,time TEXT,payload TEXT NOT NULL,PRIMARY KEY(date,time))`。每条数据为当日累计快照，不是本小时增量。同一业务日期与时点重试是更新该主键，不产生新行；新小时才追加。真正的历史分时数据来自当时快照，后来取「今天累计」不能倒填成过去小时。补历史需源备份或明确按 #event_time 截止重查；无法还原则标缺失。

业务小时 `01:00`…`24:00`；00点定时写入前一日期 `24:00`。所有标题与显示截至时间用整点，不带采集分钟；记录 observedAt 可保留真实时间以便审计。

联合 payload 包含 `ta`、`paidTa`、`gravity.paid/total`、`period`、来源信息；字段说明见指标表。英雄有买量及转化两个 SQLite，历史导出按日期小时交集，只展示完整配对记录。

## 底档与跨天

- 联合基准2026-11-16 24:00设置 `baseline:true`，已确认的数据不重算。其注册380、注册成本9.63、付费成本81.36等保留人工底档。
- 次日每次取数可更新前一日 / 历史24点行的留存，其他历史值保持；缺失新留存不覆盖已知留存。
- 正式展示包含**历史所有日期的24点行**与最新日期各小时行；旧日期中间小时仅从正式视图隐藏，数据库不删。
- 累计新进 / 收入 / 消耗 = 起始日至前一天各日24点合计 + 当天当前累计，不能把当天9点、10点等累加。
- 缺某一天24点时，不能捏造跨日累计；保持缺失并查漏档。
- 只读观察按钮生成唯一文件名副本，不锁定正式累计文件，不调用追加，不修改源库。

## 归档副本

运行 `scripts/archive-project.py` 生成时间戳目录，不改正式库 / 配置 / 定时。SQLite 使用只读连接与 backup API 一致性复制，再导出聚合JSON以便 Git diff。输出报表、原始聚合导出、配置与操作日志分类保存；敏感认证字段脱敏，登录资料和密钥文件排除。

`manifest.json` 记录文件 SHA256、数据范围、来源与排除说明；快照分文件完成，不宣称不同数据库在完全同一毫秒取样。归档是灾备 / 观察材料，不直接覆盖新线上数据。恢复时先对比最新时点与人工记录，重新授权凭据，定时默认关闭，独立预览后上线。
