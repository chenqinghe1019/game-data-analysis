# 仓库维护与唯一来源

本规则自2026-11-20生效。目录暂不大搬迁，生产脚本、SQLite、Windows任务与Webhooks均保持原路径。

## 各类资料维护在哪里

| 内容 | 维护源 | 其他位置 |
|---|---|---|
| 游戏身份、系统编号、入口与技能职责对应 | `catalog/project-registry.json` | 自动生成PROJECT_INDEX / SKILL_INDEX，不驱动生产参数 |
| 当前稳定指标 / 支付 / 身份 / 成熟规则 | `knowledge/` Canonical层 | 专业技能引用；已登记的通用参考文件自动生成 |
| 埋点完整规格、历史SQL等已存在资产 | 原tracking YAML、`sql/`、`游戏项目/` | 不复制成第二个权威版本，索引指回源文件 |
| 小时报实现、版式与特定业务规则 | 源码及 `projects/beite-hourly-report/docs/` | 技能references与压缩包由源文档生成 |
| 当前进度 / 缺失资料 / 接手方法 | `projects/auto-project/` 对应Markdown | 交接技能参考与知识包由这些文件生成 |
| 专门的技能操作步骤 / 复核清单 | 对应技能SKILL / 专用references | 没有相同Canonical源时保留原技能维护位置 |
| ChatGPT插件 | 已发布版本及 `plugins/.../sync-state.json` 镜像 | GitHub不擅自重写已发布快照，不自动发布或安装 |
| 阶段结论、旧材料、真实数据 | 原归档、memory、materials、archives | 不视为实时配置或永久口径 |

`catalog/generated-state.json` 列出生成副本、打包输入、内容指纹和压缩包SHA256。只修改源文件；直接改生成参考文件会被检查判为不同步。

## 日常更新

```text
修改已确认的源文档或注册表
python scripts/repo-maintenance.py build
python scripts/repo-maintenance.py check
提交源文件、生成副本、索引、压缩包和版本清单
```

`build` 不访问业务系统、不读取凭据、不改本机安装、不刷新运行快照；相同内容生成相同压缩包。清单使用内容指纹而非当前Git提交号，避免每次提交导致自身过期。

旧的两个package脚本继续可用，改为调用统一构建器。它们默认只构建；需要更新本机技能时明确加 `--install`。构建本身不会更新已安装的Codex技能、GPT Knowledge或云端插件。

## 自动检查的范围

GitHub每次push和PR运行注册表检查、生成文件同步检查、技能元数据、维护入口链接、凭据特征扫描及小时报离线业务断言。没有登录、取数、截图渲染、推送和定时操作，也不自动提交修复。

注册表发现同一系统编号对应多个上下文时，必须逐项标记requiresContext并写明说明。44的当前重叠显式保留，不能借整理目录给游戏改名或统一表号。

现有插件镜像有自己的版本与哈希基线，检查时应验证快照未被意外改动；新发布由原发布流程更新镜像，不把它和Codex技能文件机械互相覆盖。

## 历史与仓库体积

旧资料不删除、不移动。今后新增资料按用途标记：current（当前规则）、historical（阶段记录）、superseded（已替代）、unverified（待核实），并标注日期 / 来源 / 替代入口；无需为排版批量重写所有旧文件。

规则、源码、关键底档和有复用价值的成品进Git；高频重复截图与临时调试输出留本机，周期归档经用户决定后单独保存。此次保留用户已授权上传的所有既有归档，没有删历史或迁移大文件存储。体积变化在CI摘要中显示，不以一个任意上限阻止正常业务资料提交。

CI是检查反馈；是否设为合并硬门槛取决于仓库分支保护设置，本次不修改分支保护。GitHub检查成功也不代表Windows生产任务与业务登录已验收。

历史文件例外只登记在 `catalog/legacy-artifacts.json` 并锁定原文件SHA256。当前旧外挂治理思维导图Excel的ZIP内部偏移异常，无法完成XML读取；原件保留且不标为已验证，文件一旦改变不再适用例外。新包不允许以此跳过校验。
