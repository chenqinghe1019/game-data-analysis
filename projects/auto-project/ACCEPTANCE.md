# 新账号接手验收样例

以下用于离线回答 / 文件检查，不要求实际发消息或改线上看板。

| 场景 | 应得结果 |
|---|---|
| 00点生成联合小时报 | 业务日期是前一天，时间为24点；取前一日累计，非新一天当前值 |
| 16日24点548新进，17日9点10、10点15新进 | 17日10点总累计563，不是573；历史24点保留 |
| 两媒体注册100/20、首日付费10/10、金额100/300 | 买量付费率20/120=16.6667%，ARPPU400/20=20，不平均各媒体比率 |
| 下方了媒体首付成本与网页不符 | 核对本次日期、APPID、父节点、原始首日付费成本，不凭消耗相同或优化师位置认定匹配 |
| 联合报买量成本 | 消耗÷数数买量首日付费人数，不是累计付费人数；16日底档保持 |
| 喵喵岛埋点验收 | 明确是52，不是27；已知本地Excel与后续提案有差异，按用户指定版本验收 |
| 数数看板进入独立报表 | 若丢失「内充用户v2不属于」过滤则拒绝把结果当同口径，回看板核查 |
| 一耍总转化率及失败分布 | 分母为所选新老用户当日活跃；失败使用结果2和剩余螺丝原值，不编死亡/波次字段 |
| 萝卜4大盘追加广告字段 | 保留原DAU、新增、充值，补充字段按其参考分母；区分两种活跃定义 |
| AppLogger三端时长 | 人均按活跃人数加权，次均按启动次数加权；最终成品单位秒，不只改列名 |
| 英雄只加--preview参数 | 仍可能追加输出目录旁的数据库；独立目录后才可做不影响正式数据的模拟 |
| 第1图成功、第2图失败 | 已确认第1图跳过，只恢复剩余确认流程；结果未知不盲目重发 |
| 找不到采集器v0.1源码 | 标记资料缺失，不把旧聊天的“已实现”当今天仍可运行 |
| 旧企微文档报640008 | 旧外部企业文档受限，不换Cookie/CDP绕过；新内部文档已经通过授权读写，不能混淆 |
| 内部文档补缺 | 群图文成功后、每天11点起、按日期小时匹配既有行；不覆盖已有值/公式，以98行为格式模板，失败不重发群消息 |

回答通过不等于真实执行通过。恢复新电脑 / 新账号时还需验证文件读写、依赖、授权及后台单实例，业务动作按实际授权范围执行。
