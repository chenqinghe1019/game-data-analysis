# 换账号与换电脑清单

目标是保留可迁移的业务知识与运行材料，不承诺账号聊天、授权和产品功能完全等价迁移。

## 换号前

- GitHub master保存最新源码、规则、STATUS与验收样例；业务运行数据使用独立归档，记录时间、来源和SHA256。
- 原账号可编辑的GPT：保留名称、说明、完整指令、Knowledge**原文件**、启用能力、Actions的接口定义与示例。密钥另存，不写GitHub。
- ChatGPT项目：保留项目指令与必要附件，提炼已确认决策、当前待办和被替代规则。当前整理覆盖两个《自动项目》分组，不代表已取得其他项目的全部云端附件。
- 个性化偏好与记忆：只保留用户愿意迁移且对工作有用的内容；不要把系统上下文当个人偏好导出。已知偏好见SKILLS_AND_CONFIG。
- 找回STATUS中的丢失源码、YAML、SLG明细等，再更新缺口状态；不要先把缺口标完成。

## 新账号在同一电脑

1. 打开相同工作区，检查GitHub可读权限与最新版本；不要重置未提交的用户改动。
2. 读取START_HERE、STATUS和根工作规范；安装所需技能，确认实际可用工具。
3. 重新连接GitHub、数数、引力和所需应用。原Windows后台可能仍在运行，**先检查端口/任务，不能再启动第二套**。
4. 本机DPAPI凭据属于Windows用户，而不是聊天账号；保留同一Windows用户时不必因GPT换号盲目删除。但新账号是否可触发相应操作，要按当前连接和权限核查。
5. 先用离线样例确认口径与路径，再用只读方式检查实时状态；不要为了验证新账号重复发正式消息。

## 新电脑

克隆仓库 → 配置Node/PowerShell/Chrome/Playwright及Excel渲染依赖 → 恢复业务SQLite副本到独立路径 → 重新登录与填写Webhook → 独立预览与验收 → 再按用户要求启用正式定时。

Windows用户DPAPI、浏览器会话、OAuth/CLI授权不能假设复制即用；它们不在仓库里。正式数据库位置和重试状态与备份分开，不能复制旧sent-slots来代替新任务配置，也不能清空旧记录来解决重复。

## ChatGPT / GPT / 插件

知识包提供指令和参考材料，不赋予本机脚本执行、数据库、定时或推送能力。新账号可用功能与插件权限以其实际界面为准。官方已公告自定义GPT迁移及退役安排，配置副本应优先保持为可复用文件，迁移前核对[官方当前说明](https://help.openai.com/en/articles/20001519-custom-gpt-retirement-and-migration-faq)。导入聊天文件不会自动恢复原侧栏、记忆、配置或全部连接权限。

本机Codex技能与仓库资料可独立于聊天账号恢复；GPT知识上传后不自动跟随GitHub更新。记录每次上传的Git提交版本，以便判断是否过时。
